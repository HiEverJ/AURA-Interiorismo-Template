01 / First steps

From template to studio.

AURA is a static, single-page HTML portfolio for interior design and architecture practices. It is edited in a text editor and can be uploaded to static hosting. It is not a WordPress theme, a CMS or a hosted website service.

STEP 01

Open the page.

Keep index.html, scss and assets together. Open the HTML file to browse. The supplied stylesheet requires no compilation.

STEP 02

Add your identity.

Replace the studio name, page metadata, favicon, descriptions, project stories and email address. Demo projects and images are illustrative.

STEP 03

Set the tone.

Choose your typography and colors. Dark is the starting appearance; the visitor can switch to Light. A saved preference is restored when storage is available.

STEP 04

Publish your files.

Upload the HTML, CSS and JavaScript together, including any local images you add. Retain their relative folder paths.

Revision status: this edition contains source analysis and corrections. No automated tests, browser checks, visual validations, screenshots or PDFs were generated. Screen and interaction review remains with the owner.

03 / Visual identity

Quiet by design.

Dark

data-theme="dark"

Light

data-theme="light"

Prata provides the editorial headings; DM Sans provides body and interface text. Both are loaded through the Google Fonts link in index.html, with serif and sans-serif fallbacks.

Change the name in the navigation and footer, the browser title, the meta description and the inline SVG favicon. Update the copy to describe your actual practice. Avoid keeping fictional project locations or unsupported claims about construction services.

Color customization

Base tokens live in scss/_variable.scss and the supplied scss/main.css. Add direct customizations to scss/enhancements.css, which is linked last.

:root {
  --bg-color: #0d1117;
  --text-main: #f4f4f0;
  --accent-color: #c9d1d9;
}
[data-theme="light"] {
  --bg-color: #f9f8f6;
  --accent-color: #8c7a6b;
}

To change the default appearance, update the fallback in assets/js/theme.js and the initial data-theme on the HTML element. Stored visitor preferences take priority. The storage key is aura-theme; if storage is unavailable, switching still works for the current page.

Replace a project

  1. Find its article class="portfolio-item…" in index.html.
  2. Replace the image URL and alternative text, then the title, category and location.
  3. Update the expandable summary label, narrative and scope. Describe real work accurately.
  4. Keep the contact link or replace it with your own case-study page if you add one.

Demo content: the four projects are illustrative concepts. Photographs are remote interior references, not proof that AURA designed the depicted spaces. No downloadable photography, drawings or built-project documentation is included.

Use your own assets

Create assets/images/ and replace remote URLs with paths such as assets/images/living-room.webp. Use optimized files and meaningful alternative text. The portfolio photographs load lazily; the hero image has priority. These are implementation choices, not measured performance results.

05 / Start a conversation

A useful, honest inquiry.

The form prepares an email draft locally and displays it for copying. “Open email app” creates a message in the visitor's configured email application. The visitor sends it themselves; the website does not submit, store or encrypt messages.

BEFORE PUBLICATION

Replace the placeholder recipient.

In index.html, replace every studio@example.com occurrence: the displayed address, its mailto: link and the form's data-recipient. Then remove the note saying the contact address is a demo.

<form id="inquiry-form"
      data-recipient="your-real-email-address"
      aria-describedby="inquiry-help">

Keep the explanation that the form only prepares a draft. The name, email, project type and message fields are required. Editing a field hides the old draft until a fresh one is prepared.

Without an email application, copy the displayed text into your preferred email service. Without JavaScript, the draft button stays disabled and the direct email link remains available. Actual website submissions require your own backend or form provider; no such integration is included.

Interaction choices

AURA includes a skip link, visible keyboard focus, labeled controls, a mobile disclosure menu and reduced-motion CSS. Continuous JavaScript parallax was removed; restrained image hover effects remain for visitors who have not requested reduced motion. These changes do not constitute an accessibility certification or cross-browser test report.

07 / Owner handoff

Give the page your signature.

  • Replace the demo identity, recipient, project narratives and reference images.
  • Use factual service descriptions and your own approved project photographs.
  • Define the customer license, asset notices, author contact and support terms before selling.
  • Upload index.html, assets and scss with their relative paths intact. Documentation and internal release notes do not need public hosting.
  • Add domain-specific sharing metadata or a sitemap if needed once the real domain is known.
  • Complete your own screen and interaction review before publication.

External fonts and photographs require network access and make requests to their providers. No analytics, CMS, booking system, hosting or backend is supplied. Only the appearance preference is intentionally persisted in browser storage.

08 / Useful answers

A little guidance.

Is this a multi-page template?

No. AURA is one continuous page, with four expandable project briefs. It is intentionally distinct from a multi-page portfolio such as NOIR.

Why are some photographs or fonts missing?

The demo loads those resources from external providers. Their availability depends on the network and provider. Replace reference images with authorized local files for control over your published assets.

Why did my base CSS change have no effect?

The selected appearance or enhancements.css may override the property. Add the matching theme selector to enhancements.css, which is loaded last.

Does the website send the inquiry?

No. It generates a local draft and opens an email link. The visitor must send the message in their email service. No delivery confirmation is shown.

Where is the work recap?

QA.txt explains the source changes and states that no tests were performed. SELLER-NOTES.txt contains listing copy and seller decisions.

Was a new PDF created?

No. The previous PDF remains unchanged. This HTML guide is the documentation created for edition 1.1.
